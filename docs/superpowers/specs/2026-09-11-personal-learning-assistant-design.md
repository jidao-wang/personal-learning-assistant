# 个人学习资料问答与复习助手设计

> 状态：设计已确认，进入实现计划
>
> 日期：2026-09-11

## 1. 产品定位

本项目是一个本地运行的浏览器 Web 应用：

> 用户创建知识库并上传自己的学习资料，系统通过一个主 Agent 判断用户任务，提供普通聊天、资料问答、复习、学习计划和学习进度统计。

项目不是固定学习资料问答程序，也不是单独的出题助手。

`C:\ai agent\agent-learning` 只用于开发者理解已有代码习惯，不作为应用默认知识库，也不会在运行时自动导入。应用的知识来源是用户在页面中上传的资料。

核心闭环：

```text
创建知识库
    ↓
上传 txt / md 学习资料
    ↓
资料问答和解释
    ↓
发起复习并在线作答
    ↓
评分、保存错题和薄弱点
    ↓
生成学习计划
    ↓
查看实际复习和答题统计
```

## 2. 已确认范围

### 2.1 用户和运行方式

- 单用户本地应用，不做登录和账号体系。
- Web 应用只绑定 `127.0.0.1`，通过 `localhost` 访问。
- 不对局域网或公网开放。
- 上传资料、数据库、向量索引、聊天记录和学习记录保存在本机。
- GitHub 仓库可以保存源代码，但不提交用户资料、数据库、向量索引或 API Key。

### 2.2 文件格式和上传

- MVP 只支持 UTF-8 编码的 `.txt` 和 `.md` 文件。
- 单个文件最大 `10 MB`。
- 支持一次上传多个文件。
- 多文件逐个处理，一个文件失败不影响其他文件。
- 上传后自动解析、清洗、切分、Embedding 和写入向量库。
- 成功后立即可以问答和复习。
- 失败文件单独显示失败原因，并可以重新上传。
- 同一个知识库内上传同名文件时覆盖旧文件。
- 覆盖只影响应用内部副本、数据库记录和向量索引，不删除用户电脑上的原文件。

### 2.3 知识库

- 必须先创建知识库，再向指定知识库上传文件。
- 支持创建、重命名、删除知识库。
- 每个知识库支持多个文件持续追加。
- 每个知识库独立持久化，应用重启后仍然存在。
- 支持显示当前知识库的文件列表。
- 支持删除单个文件、清空当前知识库和删除整个知识库。
- 删除操作同步清理应用副本、SQLite 记录和 Chroma 向量。
- 不同知识库可以存在同名文件。

### 2.4 当前知识库

- 聊天页面顶部始终显示知识库选择器。
- 可选择一个知识库，也可选择“无知识库”。
- 选择“无知识库”时允许普通聊天。
- 资料问答、复习和学习计划需要选择知识库。
- 用户切换知识库后自动创建新的聊天会话。
- 原聊天会话保留，且记录当时绑定的知识库。
- Agent 只检索当前选中的知识库。

### 2.5 Memory

- 全局 Memory 只保存用户明确要求记住的偏好。
- 例如用户说“记住我喜欢简洁回答”，才保存回答风格偏好。
- 普通聊天内容不自动写入长期 Memory。
- 复习成绩、错题和薄弱知识点自动保存。
- 学习记录和薄弱点按知识库隔离。
- 全局偏好对所有知识库生效。
- 不提供独立的记忆管理页面。

### 2.6 资料问答规则

- 普通聊天不调用 RAG。
- 用户可以说“不要查资料”“只聊天”“不用知识库回答”，强制进入普通聊天，不调用 RAG。
- 用户可以说“只根据资料回答”，强制使用当前知识库。
- 用户可以说“允许使用通用知识”，允许在资料未命中时使用大模型通用知识。
- 未明确指定时，资料问答先检索当前知识库。
- 有检索结果时，优先依据资料回答并显示引用。
- 没有检索结果时，默认允许使用通用知识，但必须明确标注内容不是来自当前知识库。
- 用户要求只根据资料但没有检索结果时，直接说明当前资料中没有找到，不使用通用知识。
- 禁止把模型自行生成的内容伪装成资料引用。
- “不要查资料”不能让需要资料的复习或计划任务被静默执行为无依据任务；这类请求应明确提示需要资料或调整请求。

## 3. 主 Agent 和任务路由

整个系统只有一个主 Agent。RAG、Memory、复习评分、计划生成和统计查询都是它可以调用的能力，不拆成多个 Agent。

```text
用户输入
    ↓
读取当前会话上下文和全局偏好
    ↓
解析用户明确指令
    ↓
结合当前知识库判断任务类型
    ↓
chat / qa / review / plan / statistics
```

任务类型：

```python
TaskType = Literal[
    "chat",
    "qa",
    "review",
    "plan",
    "statistics",
]
```

路由优先级：

1. 识别用户明确的覆盖指令。
2. 检查当前是否选择知识库。
3. 判断用户是在聊天、资料问答、复习、计划还是统计。
4. 进入对应节点或调用对应工具。

典型行为：

```text
“你好”
→ chat
→ 直接调用聊天模型
→ 不调用 RAG

“不要查资料，解释一下 Agent”
→ chat
→ 不调用 RAG

“根据当前资料解释什么是 Agent”
→ qa
→ 检索当前知识库
→ 返回答案和引用

“根据当前资料生成选择题和简答题”
→ review
→ 创建复习会话
→ 进入复习工作区

“根据当前资料帮我制定学习计划”
→ plan
→ 读取资料和用户偏好
→ 生成计划并进入计划工作区

“统计我最近的答题情况”
→ statistics
→ 读取 SQLite 学习记录
→ 返回统计结果
```

## 4. 页面设计

应用包含以下页面或工作区：

```text
聊天
知识库
复习
学习计划
学习进度
```

### 4.1 聊天页面

聊天页面是主 Agent 的自然语言入口，包含：

- 当前知识库选择器。
- “无知识库”选项。
- 会话消息列表。
- 消息输入框和发送操作。
- 资料问答引用展示。
- 发起复习的结果入口。
- 发起学习计划的结果入口。

聊天页面负责发起任务，不负责承载完整的复习答题表单或完整计划编辑器。

### 4.2 知识库页面

知识库页面包含：

- 知识库列表。
- 创建知识库。
- 重命名知识库。
- 选择当前知识库。
- 文件列表。
- 多文件上传。
- 文件处理状态和失败原因。
- 删除单个文件。
- 清空当前知识库。
- 删除知识库。

### 4.3 复习工作区

复习工作区是独立页面，不是另一个 Agent。

聊天中可以发起：

```text
“根据当前知识库生成一套复习题”
```

主 Agent 创建复习会话后，聊天页面显示入口并进入复习工作区。

复习设置：

- 默认使用当前知识库全部文件。
- 用户可以选择一个或多个文件作为本次复习范围。
- 用户分别设置选择题、判断题和简答题数量。
- 未选择的题型数量为 `0`。
- 至少选择一种题型。

作答控件：

- 选择题使用单选按钮。
- 判断题使用“正确”和“错误”选项。
- 简答题使用多行文本框。
- 支持保存草稿。
- 统一提交本次答案。
- 提交后锁定本次答案，结果页展示评分。

评分方式：

- 选择题由程序根据标准答案自动评分。
- 判断题由程序根据标准答案自动评分。
- 简答题由大模型根据当前资料、参考答案和评分标准评分。
- 简答题评分请求必须包含选定资料的检索片段。
- 简答题结果需要保存评分理由、得分和资料引用。
- 如果资料不足以支持评分，结果标记为“依据不足”，不伪装成确定结果。

结果区域显示：

- 总体得分。
- 作答题数和正确题数。
- 每道题的用户答案。
- 每道题的参考答案。
- 每道题的得分和解释。
- 资料来源和切片引用。
- 错题和薄弱知识点。

### 4.4 学习计划工作区

学习计划由聊天发起：

```text
“根据当前资料帮我制定学习计划”
```

Agent 先读取当前知识库和全局偏好。缺少学习目标、截止日期或每天可用时间时，只追问缺少的信息；信息充分后生成一份完整计划。

计划工作区支持：

- 查看完整计划。
- 直接编辑计划。
- 保存修改后的计划。
- 从聊天要求 Agent 重新生成计划。
- 重新生成时默认使用当前知识库全部资料，也允许选择一个或多个文件。

计划是一个完整的可编辑文档。即使计划文本中包含按天或按阶段的建议，应用也不创建独立的每日任务记录，不提供每日打卡，不记录计划完成率。

### 4.5 学习进度页面

进度页面支持两个视图：

- 当前知识库。
- 全部知识库。

只统计实际复习和答题记录：

- 复习次数。
- 作答题数。
- 正确率。
- 平均得分。
- 错题数量。
- 薄弱知识点。
- 选择题、判断题和简答题的表现。

不把聊天次数、上传文件数量或学习计划完成情况算入学习进度。

## 5. 技术架构

### 5.1 整体结构

```text
浏览器原生 HTML/CSS/JavaScript
              ↓
FastAPI API
              ↓
LangGraph 单一主 Agent
              ↓
chat / qa / review / plan / statistics
              ↓
SQLite + Chroma + OpenAI 兼容接口
```

### 5.2 代码风格约束

代码保持接近 `C:\ai agent\agent-learning` 中已有练习，优先直观和可讲解性：

- 使用 `Python + FastAPI + Pydantic`。
- 配置使用 `dataclass`、`python-dotenv` 和 `Path`。
- 使用原生 `sqlite3` 和简单 SQL，不引入 ORM。
- 使用 `TypedDict + StateGraph + 节点函数 + 条件路由`。
- 使用明确的工具函数、参数模型和工具注册表。
- 聊天使用 `OpenAI(api_key, base_url)`。
- Embedding 使用独立的 `DashScopeEmbeddingAdapter`。
- 向量库使用 `Chroma` 的持久化目录。
- 前端使用原生 HTML/CSS/JavaScript，不引入 React、Vue 或 Next.js。
- 多文件索引处理采用简单的同步流程。
- 使用 `pytest` 测试确定性逻辑，外部模型和 Embedding 使用 mock。

不在 MVP 引入：

- 多 Agent、Supervisor 或 MCP 深度集成。
- React、Vue、Next.js 等复杂前端框架。
- SQLAlchemy、Redis、Celery、消息队列。
- Neo4j、知识图谱或多向量数据库。
- 云端用户体系和公网部署。
- PDF、DOCX、OCR 或复杂文档解析。

### 5.3 模型配置

聊天和 Embedding 分开配置：

```env
DASHSCOPE_API_KEY=你的密钥
DASHSCOPE_BASE_URL=https://dashscope.aliyuncs.com/compatible-mode/v1
CHAT_MODEL=qwen-max
EMBEDDING_MODEL=text-embedding-v4
EMBEDDING_DIMENSION=
```

配置规则：

- API Key 只从 `.env` 读取。
- 聊天模型通过 OpenAI 兼容接口调用。
- Embedding 模型通过独立适配器调用。
- 文档和查询使用同一个 Embedding 模型。
- Embedding 批量处理时按返回的 `text_index` 排序。
- 校验返回向量数量和输入文本数量一致。
- 更换 Embedding 模型后必须重建受影响的索引。

### 5.4 文档索引

```text
上传文件
    ↓
校验扩展名、大小、UTF-8 编码和文件名
    ↓
保存应用内部副本
    ↓
清理同名旧文件的向量和数据库记录
    ↓
读取并清洗文本
    ↓
按文本结构切分
    ↓
调用 DashScope Embedding
    ↓
写入当前知识库的 Chroma collection
    ↓
更新 SQLite 文件状态
```

每个知识库使用独立的 Chroma collection。每个切片至少保存：

```text
knowledge_base_id
file_id
source
title
chunk_id
content_hash
index_version
```

切片 ID 使用稳定规则生成，使同一文件覆盖和删除时能够定位旧切片。检索结果保留原文、文件名、切片编号和相似度，作为引用依据。

### 5.5 数据边界

```text
应用文件目录
└── 用户上传的 txt / md 副本

SQLite
├── knowledge_bases
├── files
├── chat_sessions
├── chat_messages
├── user_preferences
├── review_sessions
├── review_questions
├── review_answers
├── weak_points
└── learning_plans

Chroma
└── 每个知识库的文本切片和向量
```

边界规则：

- 上传资料原文不写入用户偏好 Memory。
- 聊天消息保存在 SQLite，不进入知识库向量索引。
- 全局偏好只进入 `user_preferences`。
- 复习结果和薄弱点带有 `knowledge_base_id`。
- 计划保存当前知识库和资料范围。
- `.env`、上传资料、SQLite 数据库、Chroma 目录和日志都加入 `.gitignore`。

## 6. 错误处理和安全边界

- 非 `.txt` / `.md` 文件拒绝并说明格式要求。
- 文件超过 `10 MB` 拒绝并说明大小限制。
- 非 UTF-8 文件单独标记失败，不影响其他文件。
- 空文件或清洗后无有效文本的文件标记失败。
- 文件名只用于应用内部存储和展示，不能直接拼接为可逃逸路径。
- 同名覆盖必须清理旧切片，避免新旧内容混合。
- 删除文件或知识库时，数据库和向量清理失败要明确记录，不静默标记成功。
- RAG 无结果时按用户选择决定拒答或使用通用知识。
- 通用知识回答必须显式标注，不得产生伪造引用。
- 模型调用错误、超时和工具错误向用户返回可理解的信息，不暴露堆栈、Key 或内部路径。
- 不在日志中记录完整 API Key。
- 复习简答题评分失败时保留题目和用户答案，并标记评分失败，允许重新评分。
- 没有当前知识库时，资料问答、复习和学习计划返回明确提示，不把任务伪装成普通聊天完成。

## 7. MVP 验收标准

至少覆盖以下场景：

1. 没有知识库时输入“你好”可以正常聊天。
2. 普通聊天不会调用 RAG。
3. “不要查资料”可以强制关闭 RAG。
4. 创建知识库并上传 UTF-8 的 txt/md 文件后可以检索。
5. 非支持格式、超过 10 MB 或非 UTF-8 文件会明确失败。
6. 多文件上传时成功文件正常入库，失败文件单独标记。
7. 同一知识库内同名文件覆盖后只能检索到新内容。
8. 删除文件后不能再检索到该文件的旧内容。
9. 不同知识库之间的资料不会互相检索。
10. 资料问答返回文件名、切片编号等引用信息。
11. RAG 无命中时能够按默认规则使用通用知识并标注来源边界。
12. 用户要求只根据资料且无命中时系统拒答。
13. 可以按文件范围生成一种、两种或三种题型的复习会话。
14. 选择题和判断题能够自动评分。
15. 简答题能够依据资料和评分标准调用大模型评分并保存结果。
16. 复习结果、错题和薄弱点按知识库保存。
17. 可以生成、编辑、保存和重新生成学习计划。
18. 计划不产生每日打卡或计划完成率记录。
19. 重启应用后知识库、文件、会话、计划和学习记录仍存在。
20. 进度页面的当前知识库和全部知识库统计结果正确。
21. API Key、上传资料、数据库和 Chroma 索引不会被提交到 GitHub。

## 8. 非目标

首期不做：

- 多用户登录和权限。
- 公网部署和局域网访问。
- PDF、DOCX、图片 OCR。
- 多 Agent 协作。
- 复杂的 FSRS/Anki 完整生态。
- 每日任务打卡和计划完成率。
- 记忆管理页面。
- 跨知识库自动检索。
- 简历或岗位 JD 第二知识域。

## 9. GitHub 参考原则

之前核对过的 StudyTutor、ai-study-assistant、OpenTutor、PageLM 等项目只作为产品交互、RAG 工程、复习机制和功能边界的参考：

- 不复制仓库代码。
- 不直接采用其多 Agent 架构。
- 不让外部项目的技术栈主导本项目。
- 最终项目保持“单一主 Agent + 多种工具”的结构。

## 10. 设计结论

本项目最终采用：

```text
用户上传资料
    ↓
多个独立且持久化的知识库
    ↓
FastAPI
    ↓
LangGraph 单一主 Agent
    ↓
普通聊天 / 资料问答 / 复习 / 学习计划 / 学习统计
    ↓
Chroma + SQLite + OpenAI 兼容聊天接口
```

这个设计保证：

- 没有资料时仍然可以普通聊天。
- 有资料时可以按知识库进行问答和复习。
- 复习有独立的作答和评分工作区，但项目本质仍是学习资料问答与复习助手。
- Memory、RAG、复习和统计边界清晰。
- 实现复杂度与已有练习代码相近。
- 项目能够逐步扩展，而不需要一开始引入多 Agent 或复杂平台能力。
